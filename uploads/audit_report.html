Executive summary

The Money Market Fund investor portal presents a clean, modern shell with a recognisable brand and a sensible primary navigation. Underneath the surface, however, the experience has a set of repeating problems that compound each other: a fixed-width layout that breaks at common desktop widths, dense data tables that overflow horizontally, information-density without onboarding or empty-state guidance, and a sprinkling of accessibility and microcopy gaps that will hurt first-time investors more than power users.

The biggest single issue is a structural horizontal-overflow bug on the dashboard that clips the right-hand column (Accounts and News) at both 1440 px and 1920 px viewports — a regression any new user would see on first login. The biggest opportunity is wrapping the existing data behind a clearer information architecture, better empty states, and tighter tables.

01 · Method & scope

Audit type

Heuristic evaluation (Nielsen's 10) combined with a structured WCAG 2.1 AA spot-check, plus an information-architecture and microcopy review. A single auditor, single session, ~45 minutes of clickthrough.

Browser & viewport

Dia browser (Chromium-based) on macOS, primary viewport 1440×900. The site renders inside a single sign-on, JS-rendered SPA at mmf.moneymarket.mn.

Coverage

13 screens covering sign-in, dashboard, four trade verticals, four wallet/account tabs, profile, password, news article, and the settings drawer.

Revision history

Rev. 1 — initial delivery, 27 findings. Rev. 2 — incorporated client review: three findings reclassified as not actually issues and removed (transparent dropdown, settings-drawer clipping, red sell-pill colour convention). F-04 (profile) rewritten around the correct read-only intent.

What this report does not cover

  • No main-flow testing included. Task-based walkthroughs of the core investor flows (sign-up, fund wallet, place primary-market order, place secondary-market order, withdraw, sell) are not in this report — they will be conducted as a separate exercise next week.
  • Mobile responsive behaviour was not testable in this session — Dia's window resize did not change the viewport reliably. Findings labelled "responsive" are based on layout structure and proportional sizing, not measured breakpoints.
  • Performance, load time, and Core Web Vitals.
  • Real user data — every observation that involves account numbers, balances, names, or transaction history has been redacted in this report.
  • Localisation correctness in Mongolian — the report flags structural microcopy issues but does not claim to evaluate translation quality.

Information architecture

IA observation: the Trade and Wallet hierarchies are parallel but visually different. Trade uses a left-nav fly-out; Wallet uses in-page tabs. This makes the relationship between "trade an instrument" and "see my holdings of that instrument" harder to grasp than it needs to be.

03 · Critical findings

F-01 · Dashboard right rail is clipped; horizontal scrollbar appears on the entire app
Critical
Where: /dashboard · Viewport 1440×900 and 1920×1080 · Affects every authenticated session.
The dashboard uses a fixed-width grid that exceeds the viewport. At 1440 px the right column showing Accounts and News begins at roughly x = 1090 but its content runs to ~1290 px, forcing a horizontal scrollbar across the entire page. At 1920 px the same overflow is reproducible because the layout uses an absolute (or min-width) container rather than fluid columns. Headings like "Хадгаламжи", "Итгэлцэл", "Нэхэмжлэх", and "Арилжааны" are truncated mid-word. News-card titles are clipped.
Fix: replace the fixed-width grid with a CSS grid such as grid-template-columns: minmax(0, 1fr) 320px;, give every grid item min-width: 0; so long labels can shrink, and let truncated titles wrap (overflow-wrap: anywhere) or apply text-overflow: ellipsis with a tooltip. Test at 1280, 1366, 1440, 1600, 1920.
F-02 · "HYYP" appears as the first label inside the sidebar with no explanation
Critical
Where: every authenticated page · Left rail · Heading above the nav list.
Fix: rename the section header to something semantic ("Main", "My account") or drop it. The pattern of "section header → menu items" is fine, but the header must mean something.

04 · High-severity findings

F-03 · Tables overflow horizontally inside their own container — two scrollbars stacked
High
Where: /trade-cd, /trade-it, /trade-inv, /trade-cp, /wallet/*.
Every trade and account page has a wide table (7–9 columns) inside a card that itself sits inside the already-overflowing dashboard grid. The result: users see a horizontal scrollbar on the page and a second horizontal scrollbar on the table. Columns like "Захиалга хүчинтэй хугацаа" wrap onto two lines while CD ticker columns ("CAPIT 1450 CD 200526") wrap onto four lines, making the row height inconsistent and the data hard to scan.

Before/after sketch — three options shown side-by-side. They can be combined: Option A & B for desktop, Option C for < 960 px.

Recommended sequence: ship Option A first (mono ticker + sticky first column) — it's the smallest diff and unblocks the page-level scrollbar fix in F-01. Then add Option B (column toggle) as a power-user feature. Option C (card list) becomes the responsive fallback once mobile work is in scope.
F-04 · Profile fields look editable but are intentionally read-only — wrong component for the intent
High
Where: /wallet/profile → Харилцагчийн мэдээлэл tab.
Last name, first name, email, and phone are rendered using the standard text-input component (rounded border, placeholder-style hint, icon affordance). The fields cannot actually be edited — that's the correct product behaviour, since KYC-bound personal data needs to go through support. The problem is purely a presentation mismatch: an editable-looking input promises an interaction the user can never complete, and there is no Save button to confirm or deny that promise. Users will click the field, try to type, and silently fail.
Fix — two options, both correct:
(a) Definition-list pattern (preferred) — render label on top, value below, no border, no icon. Apply optional masking on sensitive fields (phone shows 955•••981). Add an explicit "Contact support to update" affordance. The user instantly knows the screen is informational, not transactional.
(b) Disabled input pattern — keep the input component but apply disabled + aria-readonly="true", lower the field's contrast and remove the focus ring. Same outcome, more code reuse, slightly weaker signal than (a).
F-05 · Empty "Анхдагч" (Primary market) sections show a header but no content or empty state
High
Where: /trade-inv, /trade-cp.
Both the Receivables and Commercial Paper pages show an "Анхдагч" header with the section frame, but no offers, no skeleton, no "No primary offerings right now" message, and no "Notify me" call-to-action. A first-time user has no way to tell whether this is a loading state, a permanent state, or a bug.
Fix: add an empty state with (1) a one-sentence explanation of what primary market means in this vertical, (2) the next expected offering date if known, and (3) a "Notify me" toggle.
F-06 · Issuer logos render at different aspect ratios; some look like contrast bugs
High
Where: Primary-market issuer cards on Trade pages.
The "Анлок Капитал" logo on /trade-it renders against a black band that bleeds into the card surface, giving the impression of a contrast failure. "Кредитех СТМ" sits on a dark navy background that collides with the white card. Logo treatment is inconsistent: some logos have transparent backgrounds, others ship with their own coloured plates baked in.
Fix: add a 1:1 logo container (aspect-ratio: 1/1; object-fit: contain; padding: 6px) with a neutral background so issuer-supplied colours don't fight the card. Enforce a min-contrast requirement on logos in the issuer onboarding flow.
F-07 · External issuer links lack a protocol and open with no rel="noopener"
High
Where: Issuer cards on /trade-cd.
The Capitron Bank link is wired as href="www.capitronbank.mn" with no https:// prefix, which makes the browser resolve it as a relative URL inside mmf.moneymarket.mn — the link silently fails. Other issuer links (Trust page) are correctly formed but lack target="_blank" rel="noopener noreferrer" for security.
Fix: normalise outbound URLs at the API or render layer; always include the scheme; always render external anchors with target="_blank" rel="noopener noreferrer" and a small "external" icon.
F-08 · KPI tiles show ₮0 with no empty-state copy or onboarding cue
High
Where: Dashboard top — "Сүүлийн 24 цагийн өгөөж" / "Нийт багц" / "Нийт өгөөж" tiles.
A brand-new investor lands on three large zero values and a flat chart. There is no "Welcome — make your first investment" treatment, no link to the Trade section, and no explanation of what "Нийт багц" includes. For an investment product, the first-time empty state is the most consequential surface in the entire UI.
Fix: when balances are all zero, swap the chart card for an onboarding card with three steps: (1) Fund your wallet, (2) Pick an instrument, (3) Place your first order. Keep the KPI tiles as zeros but annotate them with a small "Start investing to see your portfolio here" caption.

06 · Accessibility (WCAG 2.1 AA) pass

This is a structured spot-check, not a full conformance audit. Findings are organised by WCAG principle and grouped with the broader audit's severity scale.

1. Perceivable

  • 1.1.1 Non-text content (A). The sign-in page logo has no alt attribute exposed via accessible name. Issuer-card buttons rely on text "Авах" only — fine. Note: red/green sell-buy colour coding is a trading-platform convention and is not flagged as a contrast issue, but make sure direction is also encoded with text or an icon for colour-blind users.
  • 1.4.3 Contrast (minimum, AA). The orange-on-blue brand combo in the sign-in hero is fine; the placeholder text inside form fields (the grey "Нэвтрэх нэр" / "Нууц үг") sits below 4.5:1 against the white surface. Several "Үүсгэсэн: 2025-04-08 15:56:18" date stamps in the News rail are #9AA0B5 on white — also under threshold for body text.
  • 1.4.4 Resize text. Because of the fixed-width grid (F-01) the layout breaks well before 200% zoom; content gets clipped rather than reflowed.
  • 1.4.10 Reflow (AA). Fails on every wide table and on the dashboard. Reflow at 320 × 256 CSS px is not provided.

2. Operable

  • 2.1.1 Keyboard. The settings gear and avatar dropdown both open with keyboard, but trap focus inconsistently — there is no visible focus ring on the menu items inside the dropdown.
  • 2.4.3 Focus order. Tabbing through the dashboard moves from the burger toggle straight to the gear, skipping the page heading and KPI tiles. Heading regions should be in the tab order via a "Skip to main content" pattern.
  • 2.4.6 Headings & labels. "HYYP" (F-02) fails as a meaningful heading; "Анхдагч" / "Хоёрдогч" are correctly used as section headings, but they lack aria-level hints when the surrounding scope changes.
  • 2.4.7 Focus visible. The brand-purple buttons get a soft glow on focus; the table sort icons and the "10 / хуудас" page-size selector do not.

3. Understandable

  • 3.1.1 Language of page. Verify <html lang="mn"> is set. The mixed Latin/Cyrillic in "HYYP" (and any English fragments such as "Commercial Paper" inside an article body) should be wrapped in <span lang="en">.
  • 3.3.1 Error identification. Login validation behaviour was not exercised, but the placeholder-driven design suggests errors will overwrite the placeholder. Use explicit labelled errors below each field instead.
  • 3.3.2 Labels & instructions. Profile inputs are unlabelled in the DOM beyond placeholder text; placeholders disappear on focus, removing the label — relevant to F-04's read-only treatment too.

4. Robust

  • 4.1.2 Name, Role, Value. Sortable column headers in the secondary-market table use ▲▼ glyph buttons without ARIA roles or pressed/active state — screen readers can't tell sort direction.
  • 4.1.3 Status messages. The page-level loading state (3–5 second blank between navigations) has no aria-live region; screen readers get nothing to announce.

08 · What's working well

This audit is mostly diagnostic, but it's worth naming the parts of the product that already work — partly because they're the right foundation to build on, partly to keep the team's morale calibrated.

Brand & visual system

The logo, brand-purple primary, and orange accent give the product a confident, modern look. Typography is consistent, line-heights are generous, and white space on cards is well-judged.

Navigation pattern

A left rail with icons + labels is the right choice for a multi-vertical investor portal. The active-item pill is clear. Once the "HYYP" issue is fixed, the rail is solid.

Form fundamentals

The sign-in page has a "Remember me", a show-password toggle, a "Forgot password?" link, and a "Sign up" link — every essential is present. The password-change form correctly requires the current password.

Trading-convention colour coding

Red for Sell and the implicit Buy convention follow trading-industry norms, which is the right call for an investor audience. Just keep a non-colour cue (icon or label) alongside it for colour-blind accessibility.

Theme & customisation

The settings drawer is a genuinely nice touch — dark mode plus four menu layouts gives investors agency over the workspace, which is uncommon in MN-market banking products.

Pagination & sort affordances

Tables consistently show pagination controls and a page-size selector. Sort affordances are present on most columns. Cleaning up the column widths (F-03) will make the whole pattern shine.

How I'd measure success

  • Onboarding activation: share of new accounts that fund the wallet within 7 days of sign-up.
  • Time-to-first-trade: minutes from first login to first executed order.
  • Dashboard scroll behaviour: percentage of sessions where horizontal scroll occurs on /dashboard — target zero after Sprint 1.
  • Customer-support tickets mentioning "where do I save my profile?" or "I can't edit my name" — target zero after Sprint 1.
  • Accessibility: automated axe-core score, plus a screen-reader walkthrough of the core sign-in → fund wallet → place order path (after the next-week flow testing).
